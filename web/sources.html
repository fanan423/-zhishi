为什么"不做"反而是加分项

1. 技术边界清清楚楚：每条渠道我都实际验证过能不能取、怎么取、取到什么程度，不是拍脑袋说"我们要打通一切"。

2. 连"被拦截"也如实写出来：部分二级单位站点部署了校方统一安全设备（返回 503 + 拦截页），这一条我们不粉饰成"已打通"，而是标注"被安全设备拦截，需人工确认后对接"。把做不到的如实写出来，是可信度的来源。

3. 合规意识是评委的加分点：学校 2026年10月刚发过《弱口令及账号权限专项排查整治》通知，此时宣称"爬教务后台"是反向踩雷；主动划出红线，说明这个作品是能落地的。

4. 唯一正当的"接入"路径是赢下比赛：大赛通知原文写明——获奖作品将通过"数智安农 / 徽农智"平台上线推广。先做出好东西，再让平台主动把你接进去，而不是现在硬闯后台。

交付形态与"可访问入口"（对照官方提交办法）

官方给了两条路：① 平台类——用 Dify / 扣子 / wiki 等平台搭的，交"可公开访问的分享链接"；② 原创代码类——自写源码，优先"可公网部署的链接"，部署不了则走路径 2（只能交演示视频）。

我们的现状：原创代码类 · 本地 Demo（无公网服务器）→ 落在路径 2。这意味着：必须交一份完整的 5 分钟演示视频，且答辩现场必须能当场跑起来——所以小程序 Demo 要保证随时可演示、不掉链子。

下一步最容易赚分的一步：如果后期能把小程序 / 网页版部署到可公网访问的地址（或迁到学校云资源），就能升到路径 1，把"能点开看的链接"一起交上去——可访问的实物，比只有视频的说服力强得多。

官方指定动作：链接设置（扣子平台流程）

若采用平台类形态（例如把智能体放到扣子上），官方教程给的路径是：

① API 部署成功后 → 点渠道 → 选 Web SDK → 再次部署；
② Web SDK 部署成功后 → 选分享链接 → 权限设为 「公开可见」 → 有效期至少 1 个月。

官方明确要求：链接失效或无法访问视为未有效提交。所以有效期必须覆盖整个评审周期——别设成 24 小时那种会过期的。
