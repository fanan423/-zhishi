## 可用，但有明确边界

| 能力 | 可用范围 | 边界（必须如实讲） |
|---|---|---|
| 理解层大模型抽取 | 构建期真调 36/36，46 条产物回流 | **不是端上实时调用**；端上只读结果，页面标注「构建期预计算」 |
| AI 推荐层 | 构建期真调 22/22，注入实用版；联网可切 `/api/recommend` | 实时模式需部署服务与凭证；服务不可达自动降级规则，不冒充 AI |
| 公开页聚合 | 20 个注册表源，11 成功 / 8 被 WAF 拦截如实记录 | 不绕 WAF、不登录、不碰教务后台；过期条目保留但不打扰 |
| 微信服务通知 | 代码链路与留痕完整 | 模板 ID 未配置，当前为「演示模式」，不冒充已真实送达 |
| 汇总多时间窗 | 3 / 7 / 30 天切换 | 只改变展示窗口，不改变通知池与筛选口径 |
| 智能体服务 | 默认 `127.0.0.1:8787`，Bearer 可选 | 对外暴露且不开鉴权会打安全警告；生产部署需自行配置 token |

## 未接入（有想法，但没有做成产品）

| 能力 | 为什么不做 |
|---|---|
| 向量 / BM25 混合检索 | 会破坏单文件、断网可演的形态；当前关键词命中 + 命中理由已能自证 |
| Gmail / Slack / Jira 等多平台通知源 | 超出「校园公开信息」合规边界，需登录或授权 |
| 多用户账号 / OAuth | 增加部署与隐私成本，与「本地数据不上云」冲突 |
| 自动同步直接写主分支 | 参考 LiGHT 做法，数据更新应走 PR 与人工确认，避免机器改坏事实源 |

---

## 明确不做（红线）

- 教务系统后台、成绩、课表、一卡通等需鉴权或个人敏感数据。
- 微信群 / QQ 群私聊内容；只接受群主同意后的公开文件。
- 绕过 WAF、伪造原文链接、把演示样例冒充真实采集。

> 一句话：知时的边界感不是「少做了什么」的借口，而是「为什么这些能信」的理由。
