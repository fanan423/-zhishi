# 知时 · 安农校园信息雷达

> **校园公开信息的智能聚合与个性化提醒智能体**
> 「农芯智」AI 智能体创新大赛 · 参赛作品说明

---

## 一、项目定位（一句话）

> **学生错失机会，从来不是因为"查不到"，而是因为根本不知道有这回事。**

本项目把分散在教务处、学院、学工、图书馆的公开通知，聚合成一张张
**"谁能报 · 剩几天 · 怎么办"** 的提醒卡片，主动送到学生面前——
做一个**会主动找你的校园信息雷达**。

**关键词**：不问也给 · 可溯源 · 划得清边界

---

## 二、真实痛点：不是懒，是信息架构问题

| 常见误解 | 真实情况 |
|---|---|
| "学生不看教务系统是懒" | 通知分散在**教务处 / 学院 / 学工 / 图书馆 / 公众号 / 班群**六个地方，学生不知道**去哪儿找**、也不知道**有这回事** |
| "问一下就知道了" | 学生不知道**该问什么**。机会错过不是因为问不到，是因为**不知道要问** |
| "学校已经有答疑助手了" | 现有助手只解决 **"你问它答"（检索）**，不解决 **"不问也能收到"（预警/推送）** |
| "让 AI 帮你读通知就行" | 只读不**核对**，用户不敢信。AI 说的每个结论都必须能**点回原文** |

**核心矛盾**：信息存在，但到达不了该看到它的人手上。

**本项目切口**：从"检索"跃迁到"**预警/推送**"——**判断发生在 AI 这边，不是发生在用户这边。**

## 三、差异化亮点（回答"凭什么不是数智安农翻版"）

这是本作品的核心竞争力，也是与"官方平台已有功能"和"普通爬虫工具"的真正分界线。

### 亮点一：理解后重构 —— 不是搬运，是读懂再重写

搬运信息谁都会。数智安农能列出通知原文，普通爬虫也能抓下来标题。

「知时」做的是 **理解层重构**：

> 把 **800 字通知压成 3 句人话**，同时**每个结论都挂着原文出处**，
> 点一下就能核对，杜绝 AI 胡说。

这叫 **可信的智能**——不是"我读给你听"，是"我读完告诉你重点，且你能查证"。

### 亮点二：全链路溯源 —— 结论可点击回原文核对

这是技术实现上的硬活，不是装饰：

- 每条浓缩要点的引文，在原文中做**字符串定位**，拿到真实起始下标
- 按下标把原文**切成片段数组**，每段标记「是否被 AI 引用过」「对应第几个要点」
- 点要点 → 原文自动定位高亮；点原文高亮句 → 跳回对应要点（**双向联动**）
- 一键"全部高亮"，一眼看清 AI 到底从原文里取了哪些句子

**换个引文，高亮位置自动跟着变**——是真定位出来的，不是写死的。

### 亮点三：边界感 —— 主动划清红线，而不是宣称"打通一切"

项目对每条数据链路都实际摸过边界，并在 Demo 中做成可视化面板：

| 渠道 | 状态 | 判断 |
|---|---|---|
| 教务处 / 学院 / 学工 / 图书馆官网 | ✅ **已跑通** | 公网公开页，robots 友好，合规 |
| 微信公众号 | ◐ **半自动** | 无公开 API，需用户主动送链接或授权转发 |
| QQ 群 | ◐ **需授权** | 机器人可收群内公开文件，须群主同意，不读私聊 |
| 数智安农 · 公开露出面 | ○ **待评估** | 仅抓未登录可见部分 |
| 微信小程序 | ○ **展示端** | 只做推送出口，**不做采集源** |
| **教务系统后台** | ✕ **明确不做** | 需登录态、含个人成绩学籍，**技术能绕但合规不能碰** |

> **为什么"不做"反而是加分项？**
>
> 1. **技术边界清楚**：每条渠道都验证过能不能取、怎么取、取到什么程度，不是拍脑袋说"打通一切"。
> 2. **合规意识本身就是评审加分点**：学校 2026 年 10 月刚发布《弱口令及账号权限专项排查整治》通知，
>    此时宣称"爬教务后台"是**反向踩雷**；主动划出红线，说明作品是**能落地的**。
> 3. **唯一正当的"接入"路径是赢下比赛**：大赛通知原文写明，获奖作品将通过
>    "数智安农 / 徽农智"平台上线推广。**先做出好东西，再让平台主动把你接进去**，
>    而不是现在硬闯后台。

### 亮点四：问知时 —— 不是"我给你看"，是"你问我答，且答案可核对"

主动推送解决"不问也能收到"，但学生打开雷达后**脑子里还会冒出具体疑问**：
"今天到底要办几件？""先从哪个下手？""我是不是漏了什么？""哪些是全校都能报的？"
"要准备哪些材料？""这数据可靠吗？"

「知时」把这些疑问做成了**13 个可计算的问答**（分六组），并给自己立了**三条铁律**：

1. **答案必须由真实字段算出**——不凭空生成；
2. **必须附「依据」一行说明算法**——如"统计口径：倒计时 = 0 的条目，共 1 条"，学生能逐条核对；
3. **算不出来就如实说"算不出来"**——数据不足时不编结论。

> **反问**：市面上的"智能助手"都在追求"答得漂亮"。「知时」追求的是"**答得可信**"——
> 宁可说"这条暂时算不出来"，也不给一个听起来合理但查不到的答案。
> 这是**可信 AI** 与**会说话的 AI** 的分水岭。

**踩坑实例（真实修复）**：最初"哪些是全校都能报的？"只按受众文本匹配"全校"，
结果把"全校第八周专业课考试安排"也当成"可报的机会"列出来。
修复：加一层**机会类标签白名单**（竞赛/奖助/讲座/图书/转专业/选课），
只有"要你去报名/参加"的类目才算机会——**学生视角的准确性，就在这种细节里。**

### 亮点五：办事日历 —— 同一份数据的第二个视角

时间轴回答"这周我还有几件事"，日历回答"**具体哪天忙、哪天能空**"。
把有截止的通知落到月历格子上，忙碌日按紧急度分四档着色，默认选中今天，
可翻月、看当天明细、展开本月全部待办。

> **关键设计**：日历与时间轴**同一批数据，不是两套事实**——
> 同一数据两种切法，结论必然自洽，不会出现"时间轴说有 5 件、日历只点了 3 件"的自相矛盾。

### 亮点六：「各花入各眼」—— 学院官网发的通知，只喂本学院学生

**每个学院都有自己的官网，这一事实本身就是"给谁看"的信号。**
一条"机械与车辆工程学院第十周考试安排"发布在**工学院官网**、考的是车辆工程各班，
就不该推给信院学生——哪怕它没写"仅限本院"。

「知时」据此立了一条规则：**通知发布在哪个学院的官网，就只推给那个学院的学生**；
图书馆 / 教务处 / 学工处这类**校级单位**发的通知，仍对全校可见。
三重防误杀兜底（用户没填学院 / 明写"全校" / 来源认不出 → 一律放行），
**宁可多推一条给本院，也不错杀一条真机会**。

> 这是"个性化推送"的**基本盘**：一位学生真正要的，是"**我们学院**的事"，
> 不是"全校所有学院的公告堆在一起"。**各花入各眼。**

## 四、合规说明（设计前提，不是补丁）

1. **数据源仅为公网公开页面** —— 教务处官网通知页、各学院官网、学生工作处、图书馆、创新创业学院等
   **任何人无需登录即可访问**的公开页面。
   等同于"人工去各大官网翻通知"的自动化，**合规、正当**。

2. **不涉及教务系统后台** —— **不登录、不代登录、不抓取任何需鉴权的内部系统**。
   所有对外表述统一使用"**聚合 / 归集 / 智能解析**"，**不使用"爬取教务系统"类表述**。

3. **不获取私域与敏感数据** —— 课表、成绩、一卡通等个人数据**一律不采集**。
   个性化仅来自"**公开信息 × 用户主动填写的关注偏好**"。
   小程序「我的订阅」页有专门的数据边界说明区块，明确列出"只用这些 / 不用这些"。

4. **用户可控** —— 关注事项、提前量、提醒方式全部由用户自行设定，
   数据存本地（小程序 `wx.setStorageSync`），不上传。

> 一句话：**我们聚合的都是别人看得见的东西，我们只是把它整理好、送到该看的人手上。**

## 五、系统架构（四层链路）

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│  采集层  │ → │  理解层  │ → │  匹配层  │ → │  提醒层  │
│ 公开页聚合│   │ AI 抽取  │   │ 画像×事件│   │ 倒计时卡片│
└─────────┘   └─────────┘   └─────────┘   └─────────┘
```

| 层 | 职责 | 关键设计 |
|---|---|---|
| **采集层** | 定时聚合公开通知页 | 静态页 + 少量动态页；仅公开源，频率受控 |
| **理解层** ⭐ | LLM 抽取 **事件类型 / 适用人群 / 截止时间 / 所需材料 / 办理入口** 五要素 | **本项目核心亮点**；输出置信度，低置信度标"待人工核对"；生成浓缩要点 + 引文锚点 |
| **匹配层** | 用户画像（年级/学院/关注类别）× 事件属性 | 仅匹配公开信息，不碰私域数据；用户可随时改订阅 |
| **提醒层** | 倒计时预警卡片 + 分类订阅 | "谁能报·剩几天·怎么办"三问式呈现；小程序服务通知 + 群内播报 |

**理解层示例（一条通知 → 结构化字段）：**

| 字段 | 抽取结果 |
|---|---|
| 事件类型 | 转专业 |
| 适用人群 | 2025级全日制本科（无处分、绩点≥2.5） |
| 截止时间 | 2026-11-18（窗口 11/10–11/18） |
| 所需材料 | 在线申请表 / 纸质表 / 成绩单(绩点≥2.5) |
| 办理入口 | 教务系统 → 转专业申请模块 |
| 关键提醒 | 窗口仅9天 / 限报一个专业 / 考核在11/25–11/28 |
| 置信度 | 96%（可直接推送） |

## 六、技术实现（对应评分表）

| 评分项 | 权重 | 本项目对应 |
|---|---|---|
| **创新性** | 30% | ①从"问答检索"到"**主动预警**"的范式跃迁；②**理解后重构 + 全链路溯源**；③**主动划清数据边界**；④**「问知时」自问自答引擎**（答案由真实字段算出、附依据、算不出就不编）；⑤**办事日历**（同一份数据的第二个视角） |
| **实用性** | 25% | 真实痛点 + 公开源即可落地 + 每个学生都用得上；小程序形态可直接触达；13 个高频疑问一问一答 |
| **技术实现** | 25% | 完整工作流编排 + 结构化字段抽取 + **原文定位算法** + **倒计时实时刷新** + **身份受众漏推/误杀防线** + **「各花入各眼」学院归属过滤** + 定时/推送链路 + 20 个校验脚本双层防线（一键 `run_all.js` 全绿） |
| **用户体验** | 20% | 三问式卡片、倒计时预警、双向联动核对、订阅全可控、置信度提示、问答带依据可核对、月历一眼看哪天忙 |

**技术栈：**

| 层 | 技术 |
|---|---|
| 采集 | `requests` + `BeautifulSoup`（或 `Playwright` 处理动态页） |
| 理解 | LLM 结构化抽取（few-shot + JSON schema 约束输出） |
| 溯源 | 引文字符串定位 + 原文切片渲染（Demo 已实现） |
| 问知时 | 13 问 6 组规则化问答（答案 100% 由真实字段派生，附依据说明算法） |
| 日历 | 月历网格（周一起始、紧急度四档着色、同源于时间轴数据） |
| 可靠性 | 倒计时按 `deadline` 实时现算 + 边界加固 + 静态/真运行双层校验 |
| 存储 | 结构化事件表（+ 可选向量库做语义检索） |
| 触达 | 微信小程序（原生）+ QQ 群机器人播报 |
| 算力 | 学校"大模型公共服务（token鲨）"，数智安农平台申请 |
