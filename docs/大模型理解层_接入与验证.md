## 〇、先纠正一个判断

早先的《项目评估报告》写过一句「**所有历史运行从未真正调用过大模型**」——**这是误判，现予更正**。

核实过程与结论：

| 证据 | 实测 |
|---|---|
| `node tools/agent.js --llm --limit 1` | 真跑通，模型 `Auto(auto)`，成功 1 条，模式 `llm`，耗时 4s |
| `push_out/agent_memory.json` | 已有 **40 条**大模型理解结果，最早一条 `2026-11-08T06:30:23Z` |
| `push_out/agent_run.json` | 最后一次 `mode=rule` 只是因为**没加 `--llm`**（默认走规则版） |
| `miniprogram/utils/cloud.js` | `CLOUD_ENABLED=false` 只影响**小程序端运行时**，不影响 Node 端智能体 |

误判原因：只看了 `agent_run.json` 的单点快照 + 文档自述，没查 `agent_memory.json`。
**教训：做名实核对时，「运行记录」和「记忆/产物」要一起看，单个快照会骗人。**

**真正的问题不是"接不上"，是"接上了没接进交付物"**：
40 条大模型产物全锁在 `push_out/`，`miniprogram/data/notices.js` 里一个 LLM 字段都没有。
于是小程序 / 网页版 / 单文件应用 / 演示视频里看到的永远是规则版浓缩 —— **模型干了活，评审看不见**。

## 一、优化思路：从「运行时在线调用」改为「构建期离线预计算 + 产物注入」

三个硬约束倒逼出来的选择：

| 约束 | 含义 | 结论 |
|---|---|---|
| 答辩必须断网可演 | 官方路径 2 要求现场演示，网络不可依赖 | 在线调用不能是主路径 |
| 小程序编译期不能 require 云 SDK | 项目文档已写明：无 `miniprogram_npm` 时编译期报「模块不存在」，`try/catch` 拦不住 | 端上跑不了云端模型 |
| 评审要看得见 AI | 技术分含「提示词编写 / 工作流编排 / 功能完整性」 | 产物必须进数据源，且页面有落点 |

因此：**Node 端离线跑模型 → 结构化产物注入数据源 → 端上只读产物**；在线调用降级为「可选增强」。
这样同时满足：真用了大模型 ✅ 断网可演 ✅ 端上零依赖 ✅ 可举证 ✅。

## 二、四层改造（本次已落地）

### L1 产物回流（核心）

`tools/agent/export_llm_fields.js`：读 `agent_memory.json`，按 `id` 注入 `miniprogram/data/notices.js`，新增 `llm` 对象。

```js
llm: {
  offline: true,              // 明确标注：不是实时调用
  model: "auto",
  at: "2026-11-15T...",
  promptVersion: "1.1.0",     // 或 "unknown"
  fields: { event_type, who, what, where, deadline, materials, summary, source_quote },
  quoteMatch: "full" | "partial" | "none",   // 引文定位等级，如实标注
  quoteIndex: 123
}
```

五条铁律：**只增字段不覆盖** / 引文三级定位如实标注 / 首次自动备份 / 幂等可重跑 / 注入前后逐条自验（除 `llm` 外原有字段必须逐字相同，否则中止并回滚）。

> 幂等实现踩过的坑：跨行正则清块会漏匹配造成嵌套；逐行状态机在「`id` 与后续字段同行」时会误删真实字段。
> 最终方案 = **以首次注入前的备份为确定性基线** + 剥离时保留 END 同行余下内容 + 数据级（而非文本级）手工改动保护。

### L2 页面落点

`miniprogram/pages/detail/detail.js` / `.wxml`：详情页 AI 卡片默认展示**离线大模型产物**，标注「构建期大模型预计算结果（非实时调用）」+ 模型 + 提示词版本 + 引文定位等级；按钮改为「联网重新理解（可选）」，云端未就绪时不清空已有结果。

`miniprogram/utils/cloud.js`：两端 `understandNotice` 统一为「离线产物优先 → 在线流式调用兜底」，与 Node 端 `tools/agent/core.js` 同一套契约（流式、JSON 输出、低温、同源提示词）。自检里那条 `stream: true` 红灯由此自然消掉。

### L3 提示词外置（对应官方技术评分点「提示词编写」）

`tools/agent/prompt.js`（Node 端）与 `miniprogram/utils/llm_prompt.js`（小程序端）逐字同源，带版本号，`check_llm_pipeline.js` 守两端一致。

**v1.1.0 的三条加固都有真实依据**（来自 38 条模型输出暴露的问题），可直接写进说明文档「提示词及关键配置优化」一节：

| 版本 | 实测问题 | 对应改进 |
|---|---|---|
| v1.0.0 | `source_quote` 出现空格断裂与「……」省略 | 明令逐字复制连续片段，禁止改写/概括/省略 |
| v1.0.0 | `deadline` 写法不统一 | 限定 `YYYY-MM-DD` 或 `null` |
| v1.0.0 | 个别字段有「据常识补全」倾向 | 强调不得依据常识推断 |

**诚实处理**：历史 14 条产物生成于提示词外置之前，版本不可考，一律标 `unknown`；本次真跑的 2 条标 `1.1.0`。绝不拿当前版本号替历史产物背书。

### L4 校验与配置

- 新增 `tools/checks/check_llm_pipeline.js`（21 项断言）：提示词同源 / 产物字段齐全 / 引文标注如实 / 两端条数一致 / 端上契约 / 报告一致，已加入 `run_all.js`。
- **顺带修了一个系统性大坑**：27 个 Python 脚本（含全部 checks）硬编码 `D:\新建文件夹\Claw\校园信息雷达`，导致在新工作区执行时读写旧目录——**此前那次「22/23 自检」验的其实是旧项目，属于假绿**。现改为 `pathlib.Path(__file__).resolve().parents[N]` 自适应，`tools/_archive/` 历史归档保留原样。
- `core.js` 的 `loadPublicConfig()` 仍从 `cloud.js` 正则抠配置（脆弱耦合），**本次未改**，列为后续项。

## 三、操作手册（顺序不可乱）

```powershell
$env:PYTHONIOENCODING = "utf-8"

# ① 真调大模型（用本地池，保证产物能回流到交付物）
$env:AGENT_SOURCE = "local"
node tools\agent.js --llm --limit 12

# ② 产物回流（--dry 可先预览；--restore 一键回滚）
node tools\agent\export_llm_fields.js --dry
node tools\agent\export_llm_fields.js

# ③ 同源导出 + 重建三种对外形态
python tools\export_mp_data_to_web.py
node tools\build_app.js
node tools\build_portal.js
python tools\build_demo.py

# ④ 全量自检
node tools\checks\run_all.js
```

> 关键：`AGENT_SOURCE=local`。不设时智能体默认 `merge`（读云端 `zhishi_notices` 表，池 156 条），
> 与本地 `notices.js` 的 123 条口径不同，跑出来的 id 有 24 条匹配不上，产物会白跑。

## 五、答辩话术（诚实版，别背错）

> **问：你们真的用了大模型吗？**
> 用了。Node 端智能体 `tools/agent.js --llm` 真调模型（`Auto`），把非结构化通知抽成八字段结构化结果，本次提交的数据源里有 16 条带 `llm` 产物，每条都带模型、时间、提示词版本和原文引文定位结果，可以逐条点开核对。
>
> **问：那小程序里为什么不用联网也能看到？**
> 因为理解层是**构建期离线预计算**：模型在构建阶段跑完，产物注入数据源，端上只读。这是刻意设计——路径 2 要求现场演示，网络不可依赖；小程序端也装不了云 SDK（编译期就会报模块不存在）。在线重新理解保留为可选按钮，但**不是主路径**。
>
> **问：这不就是"预先算好"吗？**
> 是，我们如实标注了：页面写明「构建期大模型预计算结果（非实时调用）」。规则版理解层同时保留作为零成本兜底，两种模式共用同一个 `understandNotice` 契约，页面零改动。
>
> **问：提示词怎么设计的？**
> 独立文件 `tools/agent/prompt.js`，带版本号。v1.1.0 针对实测暴露的三类问题做了加固（引文逐字复制、日期格式、禁止常识补全），说明文档第三章有「问题—改进」对照表。
