# 知时智能体 · 接入与部署文档

> 面向对象：要把「知时智能体」接入知时平台（小程序 / 网页）并**真跑起来**的人。
> 本文件只讲怎么把它跑起来、怎么对接、怎么排错。
> 不讲"愿景"，凡是没做到的一律写进文末《已知限制》，不粉饰。

---

## 0. 一句话说清它是什么

知时智能体是知时平台背后的**主动推送引擎**：它在服务端（或你本机）常驻，
按六步链路自己跑完一轮 —— **载入通知池 → 准入闸门 → 读画像 → 理解 → 匹配打分 → 决策主动送达**，
把"今天该主动提醒你哪几件事、凭什么提醒你"算成一份结构化清单。

**它与"打开小程序才现算"的区别，是它存在的全部理由：**

| | 本地算法（push.js / store.js） | 智能体服务（本文件所述） |
|---|---|---|
| 什么时候算 | 你**打开**小程序/网页时 | 服务端**常驻**，按点自己跑 |
| 用没用大模型 | 没有，纯规则 | 可选真调大模型做理解 |
| 关掉应用后 | 什么都不发生 | 照样在跑，结论已备好 |
| 结论权威性 | 与智能体同源一致 | 加了 LLM 理解，信息量更大 |

> 换句话说：本地算法治"我来了它才想"，智能体治"我不来它也想"。
> **两端算法同源**（`miniprogram/utils/*` ↔ `web/zhishi-core.js`），
> 由 `tools/checks/check_parity.py` 机器守卫，不会漂。

## 1. 架构总览（先看这张图，再看代码）

```
                  ┌──────────────────────────────────────────┐
                  │        知时智能体（三件套）               │
                  │                                          │
   小程序 ──┐     │  tools/agent/core.js     核心引擎（纯函数）│
            ├─────┼─→ 六步链路，CLI 与 HTTP 服务共用          │
   网页   ──┤     │                                          │
            │     │  tools/agent.js        CLI（薄壳）         │
   定时任务 ─┘     │    · --llm / --every / --quiet / --json   │
                  │                                          │
                  │  tools/agent/server.js   HTTP 服务（生产） │
                  │    · 零外部依赖，只用 Node 内置 http/fs    │
                  └──────────────────────────────────────────┘
                              ↑                ↑
                    小程序客户端           网页客户端
              miniprogram/utils/agent.js  web/zhishi-agent.js
                    （wx.request）          （fetch）
                              │                │
                     同一套接口契约：digest / status / notices / setBase
                              │                │
                      ┌───────┴────────────────┴───────┐
                      │  服务不可达 → 自动降级本地算法   │
                      │  并**如实标注**降级（不假装成功） │
                      └────────────────────────────────┘
```

**五个文件，各司其职：**

| 文件 | 角色 | 什么时候用它 |
|---|---|---|
| `tools/agent/core.js` | 核心引擎，六步链路纯函数 | 被 CLI 与服务 require；不要直接跑 |
| `tools/agent.js` | 命令行入口 | 手动跑一轮 / 挂定时任务 |
| `tools/agent/server.js` | HTTP 服务 | 给小程序/网页/第三方提供接口 |
| `miniprogram/utils/agent.js` | 小程序客户端 | 小程序页面调用 |
| `web/zhishi-agent.js` | 网页客户端 | 网页（已由 build_app.js 注入 知时.html） |

## 2. 运行环境与依赖

### 2.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **≥ 18**（推荐 20/22） | 需要全局 `fetch`（18+ 自带）；本项目实测 22.22.2 |
| 操作系统 | Windows / macOS / Linux 均可 | Windows 上是主要开发环境 |
| 网络 | 可选 | 只读云端通知池时需要；纯本地跑不需要 |
| 小程序 | 微信开发者工具 | 真机调试需 https 域名白名单 |

### 2.2 依赖

**运行时依赖：零。** `tools/agent/server.js` 只用 Node 内置模块
（`http` / `fs` / `path` / `url` / `crypto`），**不装任何 npm 包也能跑**。

唯一的外部依赖是**可选的**：

```jsonc
// package.json（节选）
{
  "dependencies": {
    "@tencent-ai/workbuddy-cloud-sdk": "^0.1.4-dev.ca27990.202610161713"
  },
  "devDependencies": {
    "jsdom": "^24.0.0"
  }
}
```

- `@tencent-ai/workbuddy-cloud-sdk` —— **只有要用云端数据源或真调大模型时**才需要。
  不装它，智能体自动退化为「本地通知池 + 纯规则」，功能照常。
- `jsdom` —— 仅**校验脚本**用（真渲染测试），不影响运行。

```bash
# 安装（可选，但推荐装齐以启用云端/LLM）
npm install
```

### 2.3 验证环境就绪

```bash
node --version          # 应 ≥ v18
node tools/agent.js --dry
```

`--dry` 表示只算不落盘，能在 1 秒内告诉你"核心引擎能不能跑通"。

## 3. 快速上手（三步跑起来）

### 第 1 步 · 跑一轮看看

```bash
# 纯规则（不联网、不调模型，最快）
node tools/agent.js --dry

# 真调大模型做理解（需要 cloud SDK + 网络）
node tools/agent.js --llm

# 机器可读输出（给别的程序消费）
node tools/agent.js --json
```

跑完会在 `push_out/` 落三个文件：

| 文件 | 内容 |
|---|---|
| `agent_run.json` | 完整六步结构（`pool`/`passed`/`matched`/`cards`/`notify`/`mode`…） |
| `今日推送.txt` | 给人看的推送清单（含"凭什么推"） |
| `推送记录_<时间戳>.txt` | 历史快照，可回溯 |

> 服务端 `/api/digest/deliver` 另落 `agent_deliver.json`（**与 CLI 的 `agent_run.json` 物理分家**，
> 互不覆盖，便于并行取用）。

### 第 2 步 · 起 HTTP 服务

```bash
# 默认 127.0.0.1:8787
node tools/agent.js --serve

# 或直接跑服务文件（等价）
node tools/agent/server.js
```

验证：

```bash
curl http://127.0.0.1:8787/healthz
# {"ok":true,"status":"alive","uptimeSec":3,"at":"..."}

curl "http://127.0.0.1:8787/api/digest?useLLM=false"
# {"ok":true,"source":"merge","via":"remote","meta":{...},"notify":[...],"silent":[...],"text":"..."}
```

### 第 3 步 · 把地址填进平台

**小程序**：改 `miniprogram/app.js` 的 `globalData.agentBase`，
或在小程序「我的订阅 → 智能体服务 → 改地址」里运行时填（写本地 storage，免发版）。

**网页**：在「我的 → 推送设置 → 智能体服务 → 改地址」里填，
或直接在 `web/zhishi-agent.js` 里用 `ZS_AGENT.setBase('https://...')`。

**未填 = 本地模式**，页面仍完整可用（会如实显示"本地模式（未部署智能体服务）"）。

## 4. 对接方式与接口清单

### 4.1 对接方式总览

智能体对外只暴露**一件事**：一个 HTTP 服务。
两端客户端（小程序 / 网页）都通过它对接，接口契约完全一致。

- **传输**：HTTP/1.1，JSON
- **编码**：UTF-8
- **认证**：可选 Bearer Token（`AGENT_TOKEN`，空 = 不鉴权，见 §5）
- **CORS**：默认 `*`（可用 `AGENT_CORS_ORIGIN` 收紧）
- **超时**：服务端请求超时 120s（`AGENT_REQ_TIMEOUT`）；客户端 20s

### 4.2 接口清单（共 13 个）

| 方法 | 路径 | 作用 | 关键入参 | 关键出参 |
|---|---|---|---|---|
| GET | `/` 或 `/api` | 接口索引（JSON，机器可读） | — | `{ok,service,version,endpoints,docs}` |
| GET | `/healthz` | 存活探针（不碰业务、免鉴权） | — | `{ok,status,uptimeSec,at}` |
| GET | `/readyz` | 就绪探针（真读通知池 + 同源算法自检，免鉴权） | — | `{ok,ready,checks:{cloud,notices,engine}}` |
| GET | `/api/version` | 版本号与能力清单（便于排错对齐） | — | `{ok,name,version,node,config,capabilities}` |
| GET | `/api/notices` | 通知池查询 | `event,q,withDeadline,sort,offset,limit,refresh` | `{ok,total,items,source}` |
| GET | `/api/notices/:id` | 单条通知 | — | `{ok,item}` |
| GET | `/api/tags` | 标签词表 | — | `{ok,count,items}` |
| GET | `/api/profile` | 读服务端画像 | — | `{ok,profile,source}` |
| PUT | `/api/profile` | 写服务端画像 | `{profile}` | `{ok,profile,source}` |
| POST | `/api/understand` | 单独理解一条通知 | `{id}` 或 `{notice}`，`useLLM` | `{ok,mode,fields}` |
| POST | `/api/run` | **跑完整一轮** | `{profile,useLLM,llmLimit,persistMemory}` | `{ok,source,...六步结构}`（含 `steps`/`pool`/`matched`/`notify`/`mode`） |
| GET | `/api/digest` | **今日主动送达清单** | `useLLM,llmLimit` | `{ok,source,via,meta,notify,silent,text}` |
| POST | `/api/digest/deliver` | 清单**落盘送达** | `{useLLM,llmLimit}` | `{ok,delivered,files,text}` |

> **`/api/digest` 是平台侧最常用的一个**：小程序简报页、网页简报页都只调它。
> 健康/就绪探针 **豁免鉴权**（方便负载均衡探测），其余接口配了 token 就要带。

### 4.3 统一响应契约

**成功**：

```json
{ "ok": true, "...": "各接口自有字段" }
```

**失败**（HTTP 状态码 + 结构化 body，**四要素齐全**）：

```json
{
  "ok": false,
  "error": {
    "code": "BAD_REQUEST",
    "message": "limit 必须是正整数",
    "hint": "示例：?limit=50"
  },
  "reqId": "a3f9c1e2-...-8b7d"
}
```

`reqId` 会同时打进服务端日志与响应头 `X-Request-Id`，**中文路径也能按 reqId 追查**。

## 5. 配置参数表

所有配置都可用**环境变量**或**命令行参数**（服务文件支持 `--key value`）覆盖。
下表**逐项对照 `tools/agent/server.js` 与 `tools/agent/core.js` 的实际读取代码**，不写未接线的键。

| 环境变量 | 默认值 | 读取处 | 说明 |
|---|---|---|---|
| `AGENT_PORT` | `8787` | server | 监听端口（也可用 `--port`） |
| `AGENT_HOST` | `127.0.0.1` | server | 监听地址（也可用 `--host`）。**要外部访问须改 `0.0.0.0`**（注意安全） |
| `AGENT_TOKEN` | 空 | server | 空 = 不鉴权；非空则要求 `Authorization: Bearer <token>` |
| `AGENT_CORS_ORIGIN` | `*` | server | CORS 允许来源，生产建议收紧成具体域名 |
| `AGENT_BODY_LIMIT` | `1048576`（1 MiB） | server | 请求体上限，超出返回 `PAYLOAD_TOO_LARGE` |
| `AGENT_REQ_TIMEOUT` | `120000` | server | 单请求超时（毫秒）。**注意键名没有 `_MS`** |
| `AGENT_MAX_CONCURRENT` | `4` | server | 并发上限，超出返回 `OVERLOADED` |
| `AGENT_LLM_DEFAULT` | `1` | server | `/api/digest` 等默认是否开 LLM（`0` 关，测试常用） |
| `AGENT_LLM_MAX_BATCH` | `20` | server | 单轮最多用大模型理解几条（控成本） |
| `AGENT_NOTICE_LIMIT` | `500` | server | 通知池上限 |
| `AGENT_NOTICE_TTL` | `60000` | server | 通知池进程内缓存时长（毫秒） |
| `AGENT_PROFILE_STORE` | `push_out/agent_profile.json` | server | 服务端画像落盘路径（也可用 `--profile-store`） |
| `AGENT_SOURCE` | `merge` | **core** | 数据源三态：`cloud` / `local` / `merge` |

**CLI（`tools/agent.js`）另有一组命令行开关**（不是环境变量，别搞混）：

| 开关 | 默认 | 说明 |
|---|---|---|
| `--llm` | 关 | 真调大模型做理解（否则纯规则） |
| `--limit <n>` | `8` | 单轮最多理解几条"没理解过的" |
| `--profile <路径>` | 内置默认画像 | 指定画像 JSON 路径（**是路径入参，不是环境变量**） |
| `--dry` | 关 | 只算不落盘 |
| `--quiet` | 关 | 只落盘不刷屏（定时任务用） |
| `--json` | 关 | 输出机器可读 JSON |
| `--every <分钟>` | `0`（不常驻） | 常驻，每 n 分钟自己跑一轮 |
| `--serve [--port n] [--host h]` | — | 转交 HTTP 服务（等价 `server.js`） |

> **LLM 持久记忆路径当前是硬编码的** `push_out/agent_memory.json`
> （`core.js` 的 `MEMORY_FILE()`），**没有环境变量可覆盖** —— 属已知限制，见 §9.2 第 8 条。

### 数据源三态（**这是最容易踩的坑，务必理解**）

数据源由 `core.loadNotices()` 决定，优先级为：
**显式传入的 `notices` > 参数 `o.source` > 环境变量 `AGENT_SOURCE` > 默认 `merge`**。

| 值 | 含义 | 何时用 |
|---|---|---|
| `local` | 只用打包进代码的通知池 | 完全离线演示 |
| `cloud` | 只用云端 `zhishi_notices` 表（RLS 允许匿名读） | 想要"实时"数据 |
| **`merge`** | **云端 ∪ 本地**（同 id 云端覆盖） | **默认**，最稳 |

> **为什么默认 merge**：云端表曾只有 33 条且多为「校内通知」，
> 纯 cloud 会让匹配数从 12 掉到 1（真的踩过）。
> merge 兼顾"云端的实时"与"本地的厚度"，两侧都不断供。
>
> **另有一个内部开关 `preferCloud`**（`core.loadNotices({ preferCloud })`，默认 `true`）：
> 传 `false` 即彻底不碰云端（等价于离线）。服务端与 CLI 均**不读** `AGENT_DATA_SOURCE`
> 这个键 —— 它不存在于代码中（历史文档误写），**以 `AGENT_SOURCE` 为准**。

## 6. 调用示例

### 6.1 curl

```bash
# 健康检查
curl -s http://127.0.0.1:8787/healthz | jq .

# 今日清单（纯规则，最快）

curl -s "http://127.0.0.1:8787/api/notices?event=%E8%80%83%E8%AF%95%E5%AE%89%E6%8E%92&limit=5" | jq '.total'

# 写画像后跑一轮
curl -s -X PUT http://127.0.0.1:8787/api/profile \
  -H 'Content-Type: application/json' \

curl -s -X POST http://127.0.0.1:8787/api/run \

```

带鉴权时加一行：`-H "Authorization: Bearer $AGENT_TOKEN"`

```js
const { runOnce, installHost } = require('./tools/agent/core.js');

(async () => {
  installHost();                    // 注入 wx 桩（复用小程序同源算法）

    useLLM: false,
    notices: null,                  // null = 自动载入（按 AGENT_SOURCE / preferCloud）
```

## 7. 功能范围

### 7.1 已实现（可直接生产用）

**核心链路（六步）**

1. **载入通知池** — 三源（cloud/local/merge），带每源条数与合并明细
2. **准入闸门** — 新鲜度（`FRESH_AFTER='2025-01-01'`）+ 低价值过滤（`LOW_VALUE_RE`）+ 非学生事项过滤（`NONSTUDENT_NEWS_RE`）
3. **读画像** — 本地 JSON / 参数注入 / 服务端落盘 三级来源，来源如实标注
4. **理解层** — 规则版（始终可用）+ 大模型版（可选，流式 + JSON，带持久记忆）
5. **匹配打分** — 与两端同源；**「理由即分数」**：分 = 理由权重之和归一化 0–100
6. **决策** — 分「主动送达 / 静默进流」两档，各条带 `reasons` 与 `reasonLine`

**生产级服务能力**

- 零外部依赖 HTTP 服务，13 个接口
- 结构化错误码（8 种）+ `reqId` 全链路日志（响应头 `X-Request-Id`）
- 请求超时 / 并发上限 / body 上限 / CORS / 可选鉴权
- 优雅退出（SIGINT/SIGTERM + 10s 强退兜底）
- 健康与就绪**双探针**，便于接负载均衡
- 通知池 TTL 缓存（`AGENT_NOTICE_TTL`，默认 60s），避免每次打云端
- 运行计数器（请求数/错误数/最近一轮）

**调度与运维**

- `--every <分钟>` 常驻轮询
- `tools/install_agent_task.ps1` 注册 Windows 计划任务（含 `-Remove` 卸载）
- 持久记忆（`push_out/agent_memory.json`），已积累 LLM 理解结果，**不重复理解**

**平台接入**

- 小程序 `digest` 页：主动送达清单 + 状态条 + 可核对元信息
- 小程序 `me` 页：智能体服务状态卡（改地址 / 触发运行 / 诚实三态）
- 网页简报页 + 推送设置页：同构区块
- 两端**可降级适配**：服务不可达自动回落本地算法，且**如实标注**

### 7.2 明确不做（也是设计选择）

- ❌ **不代发微信/短信**：微信服务通知必须由用户本人授权（合规硬要求），
  智能体只把"什么时候该发什么"算好，实际下发交由平台侧的订阅消息通道。
- ❌ **不读任何私域数据**：不碰课表 / 成绩 / 学籍 / 一卡通。
  只读公网公开通知页 + 用户自己填的画像。
- ❌ **不做用户系统**：没有登录、没有多租户隔离，画像即身份（见 §9）。

## 8. 错误处理与异常应对

### 8.1 错误码表

| code | HTTP | 触发条件 | 客户端应该怎么办 |
|---|---|---|---|
| `BAD_REQUEST` | 400 | 参数类型/范围错误、JSON 解析失败 | 改参数；读 `hint` |
| `UNAUTHORIZED` | 401 | 配了 token 但未带/带错 | 补 `Authorization` 头 |
| `NOT_FOUND` | 404 | 未知路径或通知 id 不存在 | 核对路径 |
| `PAYLOAD_TOO_LARGE` | 413 | body 超 `AGENT_BODY_LIMIT` | 分批或加大上限 |
| `OVERLOADED` | 429 | 并发超 `AGENT_MAX_CONCURRENT`（或服务正在关闭） | 退避重试 |
| `TIMEOUT` | 504 | 超过 `AGENT_REQ_TIMEOUT`（默认 120s） | 减少 `llmLimit` 或关 LLM |
| `UPSTREAM_UNAVAILABLE` | 502 | 云端/LLM 不可达 | 降级本地（客户端已自动做） |
| `INTERNAL` | 500 | 未预期异常 | 拿 `reqId` 查日志 |

### 8.2 异常场景与既定行为

| 场景 | 已成既定行为 |
|---|---|
| 云端通知池不可达 | 自动回落本地池，`source` 如实标 `local`，**不报错** |
| 大模型不可用 / 超时 | 自动走规则版，`mode` 标 `rule`，**不假装调过模型** |
| 客户端配了服务但连不上 | 降级本地算法 + `degraded:true` + `degradeReason` |
| 网页环境无 `fetch`（老 WebView） | 明确拒绝并降级，**不抛 ReferenceError** |
| 单条通知结构缺字段 | `normalizeRow` 兜底成空值，不崩 |
| 通知池为空 | `digest` 返回空 `notify`/`silent`，页面显示"今天没有需要主动送达的事" |
| 画像缺字段 | 用默认画像补齐，来源标 `default` |
| LLM 返回截断的 JSON | `extractJson` 三级抢救（补括号 / 丢残缺键值对），能救回中文摘要 |

### 8.3 服务端健壮性自测

```bash
node tools/checks/check_agent_service.js
```

会**真起一个临时服务**（默认端口 8799，可用 `AGENT_TEST_PORT` 改）逐个打接口，
覆盖：冒烟 / 契约 / 错误码 / 边界（超大 body、非法 JSON、无 Content-Length）/ 鉴权 / 中文路径。
**脚本自己打印"X 项通过 / Y 项失败"，以实际输出为准**（本文不写死数字，避免与代码漂移）。

## 9. 已知限制与未完成项

> 这一节是本文件的**重点之一**。下列都是真的，不藏。

### 9.1 架构限制

1. **无用户系统 / 无多租户隔离**
   服务端画像只有**一份**（`AGENT_PROFILE_STORE` 指向的单文件 / 单行）。
   多人同时用会互相覆盖。**生产部署前必须补**：按 `owner_id` 分表 + 鉴权。
   目前定位是"单人 / 演示 / 内网"。

2. **服务默认只监听 `127.0.0.1`**
   外网访问须显式 `AGENT_HOST=0.0.0.0`，且**强烈建议**同时开 `AGENT_TOKEN`。
   目前没有内置 HTTPS（生产应由 Nginx/Caddy 反代终止 TLS）。

3. **通知池上限 500 条**（`AGENT_NOTICE_LIMIT`）
   全量池超 500 时会截断。当前真实数据约 156 条（merge 后），暂未触及。

4. **通知池缓存 60s**（`AGENT_NOTICE_TTL`）
   云端数据更新后最多 60s 才可见。追求秒级实时需自行调 TTL 或加失效钩子。

5. **并发上限 4**
   超出的请求直接 `429`，**不带排队**。高并发场景需换带队列的实现或加多实例。

### 9.2 功能缺口

6. **微信服务通知未真发**
   订阅消息模板 ID（`miniprogram/utils/wxnotify.js` 的 `TEMPLATES.tmplId`）
   仍为空，所以走"完整交互 + 登记"但**暂不真发**（页面如实标"演示模式"）。
   配好模板 ID 后自动转真发，用户无需重操作。

7. **LLM 理解未做批量并发**
   单轮最多 `AGENT_LLM_MAX_BATCH=20` 条，**串行**处理。
   池子大时较慢（实测 ~800ms/条），需要提速得改并发池。

8. **持久记忆路径硬编码、无过期策略**
   `agent_memory.json` 的路径由 `core.js` 的 `MEMORY_FILE()` 写死，**没有环境变量可改**；
   且该文件只增不减。通知内容变了会按 `bodyHash` 重算，但旧条目不会清理。
   长期运行需加路径参数 + TTL 或容量上限。

9. **调度精度粗**
   `--every` 与实际计划任务都是分钟级，**不保证准点**。
   对"截止当天准点提醒"要求高的场景，需接更精确的调度器。

### 9.3 未验证 / 存疑

10. **多实例部署未验证**
    两个服务实例共享同一 `AGENT_PROFILE_STORE` 文件会互相覆盖；
    内存计数器也不共享。多实例需先解决状态外置（Redis/DB）。

11. **真机小程序未端到端验证**
    小程序客户端在 Node 模拟环境（jsdom + wx 桩）全绿，
    但**真机 + 真实 https 域名白名单**链路未实测（缺 AppID/域名）。
    本地开发可用"不校验合法域名"绕过，正式环境需自行配置。

12. **云端表结构变更未做版本协商**
    当前按 `zhishi_notices` 现有列名硬编码（`normalizeRow`）。
    若云端改列名，需同步改 `core.js` —— 没有 schema 版本握手。

13. **云端 SDK 依赖为 dev 版本号**
    `@tencent-ai/workbuddy-cloud-sdk` 当前锁在 `^0.1.4-dev.…` 开发版；
    正式上线前建议锁定一个稳定版并回归 §10 全部校验。

## 11. 排错速查

| 现象 | 先查这里 |
|---|---|
| 页面显示"本地模式（未部署智能体服务）" | 正常 —— `agentBase` 没填。填了就变"已连接" |
| 页面显示"服务未连接（已降级本地算法）" | `curl <base>/healthz` 通不通；小程序看域名白名单 |
| `mode` 一直是 `rule` | 没装 cloud SDK，或缺网络，或 `AGENT_LLM_DEFAULT=0` |
| 匹配数特别少（个位数） | 数据源设成了 `cloud`；改回 `merge`（默认，用 `AGENT_SOURCE`） |
| 某条通知反复被理解 | `agent_memory.json` 被删了；它会重新积累 |
| 服务起来但外部打不通 | `AGENT_HOST` 还是 `127.0.0.1`；或防火墙 |
| 报 `OVERLOADED` | 并发超 4；退避重试或加 `AGENT_MAX_CONCURRENT` |
| 报 `PAYLOAD_TOO_LARGE` | body 超 1 MiB；分批或加 `AGENT_BODY_LIMIT` |
| 报 `TIMEOUT` | 大模型太慢；降 `llmLimit` 或调大 `AGENT_REQ_TIMEOUT` |
| 中文路径 404 | 用 `encodeURIComponent` 转义（Node http 拒绝未转义 path） |
| 端口被占 | `AGENT_PORT=8788 node tools/agent.js --serve` |
