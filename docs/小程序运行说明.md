# 知时 · 小程序运行说明

> 「知时 · 安农校园信息雷达」——微信原生小程序（非网页套壳），同时提供一份
> **浏览器就能点开的交互 Demo**。两者**数据与算法完全同源**。

---

## 〇、两种"跑起来"的方式

| 方式 | 适合谁 | 怎么开 | 要不要装东西 |
|---|---|---|---|
| **A. 交互 Demo（网页）** | 想 10 秒看效果的任何人 | 双击项目根目录的 `交互Demo.html` | **不用**，浏览器直接开 |
| **B. 真机小程序** | 想进微信、要提交比赛的你 | 微信开发者工具导入 `miniprogram/` | 装微信开发者工具 |

两者跑的是**同一份逻辑**（`web/zhishi-core.js` ↔ `miniprogram/utils/`）和
**同一份数据**（`web/zhishi-data.js` 由 `miniprogram/data/notices.js` 自动导出）。
所以 Demo 里看到的排序、理由、问答，和小程序里**逐字一致**。

## 一、方式 A：交互 Demo（推荐先看这个）

**双击 `交互Demo.html`**（项目根目录），浏览器打开即用。手机外框、底部四个 Tab，
全部可以真点：

- **📡 雷达**：推送流按"优先办 / 稍后看"主次分层；只推和你身份、关注相符的通知，点进详情可核对「和我有关吗」
  （理由链 + 分数都在详情页）；左上红点=未读，**长按卡片**弹出菜单可标记已读 / 删除。
- **🔍 搜索**：输入关键词或点热词，结果标注**在哪命中的**（标题/原文/标签），
  点进详情看 AI 浓缩要点 + **原文出处定位**。
- **💬 问知时**：自然语言提问（"今天有什么非要办的？"），回答附**依据**说明；
  下方办事日历可翻月、点有事项的日子看当天要办什么。
- **👤 订阅**：改身份/年级/学院/关注标签，回「雷达」看推送流**实时重排**——
  这就是"千人千面"。

> 内容与算法改自真源文件，Demo 由 `python tools/build_demo.py` 自动生成，
> 不是手抄一份，所以永远不会和真源码漂移。

https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

### 2. 导入项目

打开开发者工具 → 「导入项目」→ 目录选择：

```
D:\新建文件夹\Claw\校园信息雷达\miniprogram
```

AppID 这一栏：

- **想立刻看效果** → 点「测试号」或直接下一步（已配置 `touristappid`，游客模式可直接编译预览）
- **要提交比赛 / 发布** → 填入你自己注册的小程序 AppID

### 3. 编译

点顶部「编译」，模拟器里就能操作。真机预览点「预览」扫二维码即可。

> **云服务是可降级的**：`utils/cloud.js` 已接云服务，但网络不可用时会
> 自动回落到 `data/notices.js` 内置数据 + 本地 storage，**离线也能完整演示**。

### 4. 建议演示顺序

1. 首页 → 看推送流（主次分层，只推相符通知）
2. **长按**一条推送 → 标记已读 / 删除
3. 点进详情 → 看浓缩要点，点一条要点看它展开**原文出处**
4. 搜索页输入「转专业」→ 看命中来源 → 点进看官网原文
5. 「订阅」页把年级从 2025级 换成 2022级 → 回首页看排序变化
6. 「问知时」问"今天有什么非要办的？" → 看回答 + 依据

## 四、核心实现点（答辩可讲）

### 1. 推送为什么是"定点"的
`utils/push.js`：**分数 = 理由权重之和**，每条推送都带一张"理由清单"
（今天截止 +40 / 还剩3天 +28 / 点名了你的学院 +22 / 你关注了它的标签 +16 …）。
非学生事项（纪委会议/值班表/经费公示）给 **-30** 直接沉底；
"面向学院报送"这类学生不用自己办的事给 **-14** 降权。
所以推给学生的每条都**站得住脚**，不是"每份通知都面向所有本科生"。

### 1.5 「各花入各眼」学院归属（本轮新增，用户点出的跨院误推）
`utils/identity.js` 的 `noticeCollege` / `matchCollege`：**通知发布在哪个学院的官网，
就只推给那个学院的学生**。例：工学院官网发的「第十周考试安排」（考的是车辆工程各班），
不再推给信院学生；图书馆/教务处这类**校级单位**发的通知仍对全校可见。
用户没填学院、或通知明写"全校/全体师生"→ 放行（**不误杀**）。两张来源词表
（学院别名表 + 校级关键词表）两端同源，由 `check_parity.py` 守卫。

### 2. 主次梯度（tier）
首页头条卡 + 中卡（三天内 **或** 分数 ≥ 50）/ 小卡（更远的归档）。
阈值 `MAJOR_SCORE = 50` 与页面层共用，**版面无倒挂**（不会出现"高分排在小卡"）。

### 3. 溯源在本地怎么做的
`store.locateQuote(raw, quote)`：把浓缩要点的引文在原文里做**字符串定位**，
返回起始下标，详情页按下标把原文切成片段数组（`quotedRaw`），
每段带 `hl`（是否被引用过）标记。**换个引文，高亮位置自动跟着变**。

### 4. 已读 / 删除
`utils/readstate.js`：本地 storage 记 `readIds` / `hiddenIds`（各留最近 500）。
不复用 push.js 的 `openedIds`——那是**反馈闭环痕迹**（引擎用它揣摩兴趣），
已读是**用户自己的书签**，语义不同，混一份会互相误伤。

### 5. 合规边界落在代码里
- 采集对象：仅 `data/notices.js` 中标注的公开单位
- 画像来源：用户在订阅页**主动填写**，存本地，不上传
- 不读取、不上传任何校内私域数据（课表/成绩/学籍/一卡通/身份证号）

## 五、校验脚本

改完代码 / 数据，务必跑一遍全量校验（**18 个脚本**）：

```bash
node tools/checks/run_all.js          # 一键全跑，看总账
```

单独跑：

```bash
node tools/checks/run_miniprogram.js       # 小程序十页真运行（484 项断言）
node tools/checks/check_demo_interactive.js # 交互 Demo 真点击（33 项断言）
python tools/checks/check_parity.py         # 两端同源守卫
python tools/checks/check_all_pages.py      # 全部展示页可打开
```

改完数据/逻辑要**重新生成 Demo**：

```bash
python tools/build_demo.py            # 依据真源重建 交互Demo.html
```
