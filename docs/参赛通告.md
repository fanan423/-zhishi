## 三、作品简介（对外声明版）

「知时」解决的核心矛盾：**信息存在，但到达不了该看到它的人手上。**

学生的通知分散在**教务处、各学院、学生工作处、图书馆、创新创业学院、微信公众号与班级群**
等多个地方，学生**不知道去哪儿找，也不知道"有这回事"**，于是错过转专业、竞赛报名、
评奖评优、讲座选课等**一旦错过不可逆**的窗口。

这不是"学生懒"，是**信息架构问题**。「知时」的做法是：

1. **聚合**——定时归集多个**公网公开**通知页；
2. **理解**——用大模型把非结构化原文抽取为结构化五要素
   （事件类型 / 适用人群 / 截止时间 / 所需材料 / 办理入口）；
3. **浓缩**——把 800 字通知压成 3 句人话，**每句都挂原文出处**；
4. **匹配**——结合用户**主动填写**的画像（年级 / 学院 / 关注类别）筛出"与我相关"的通知；
5. **预警推送**——以"谁能报 · 剩几天 · 怎么办"倒计时卡片**主动送达**。

## 四、核心创新点（声明）

| # | 创新点 | 一句话说明 |
|---|---|---|
| 1 | **范式跃迁** | 从"你问它答（检索）"到"**不问也能收到（预警/推送）**" |
| 2 | **真·触达闭环** | 不止在应用内排序，而是走**微信订阅消息**把提醒送到你手机上（关掉小程序也能收到）；无模板时**如实标注"演示模式"**，绝不冒充已通 |
| 3 | **可推演·可复核的触达时间线** | 把每条通知从发布到截止摊在时间轴上，标出**哪天会找你、找你几次**——全部由真实发布日与截止日算出，**断网也能演** |
| 4 | **理解后重构 + 全链路溯源** | 不只搬运原文，而是读懂再重写；每条结论**可点击回原文核对**，双向联动高亮 |
| 5 | **主动划清数据边界** | 实测每条链路边界，明确声明"**教务系统后台永不接入**"——合规即竞争力 |
| 6 | **「问知时」自问自答引擎** | 13 个高频疑问一问一答，答案由**真实字段算出**、附「依据」说明算法、**算不出就说不算得出** |
| 7 | **办事日历** | 同一份数据的第二个视角，回答"具体哪天忙、哪天能空"；与时间轴**同源不打架** |

## 六、合规声明（本作品的第一条设计前提）

1. **数据源仅为公网公开页面**——教务处官网通知页、各学院官网、学生工作处、图书馆、
   创新创业学院等**任何人无需登录即可访问**的公开页面。
   等同于"人工去各大官网翻通知"的自动化，**合规、正当**。
2. **不涉及教务系统后台**——**不登录、不代登录、不抓取任何需鉴权的内部系统**。
   所有对外表述统一使用"**聚合 / 归集 / 智能解析**"，**不使用"爬取教务系统"类表述**。
3. **不获取私域与敏感数据**——课表、成绩、学籍、一卡通等个人数据**一律不采集**；
   个性化仅来自"**公开信息 × 用户主动填写的关注偏好**"。
4. **用户可控**——关注事项、提醒方式全部由用户自行设定，数据**存本地**（小程序 `wx.setStorageSync`），**不上传**。
5. **采集礼仪**——详情页抓取后 `sleep(0.4)`，单站点限额、翻页有上限，**不冲击对方服务器**。

> 一句话：**我们聚合的都是别人看得见的东西，我们只是把它整理好、送到该看的人手上。**

## 七、运行环境与现场演示预案

| 项 | 配置 |
|---|---|
| 操作系统 | Windows 10 / 11（可迁移 Linux） |
| 现场演示形态 | **双击 `知时门户.html`**（单文件，零依赖，离线可用） |
| 备用形态 | 微信开发者工具导入 `miniprogram/`（已配 `touristappid` 游客模式） |
| 依赖（仅采集/构建用） | Python 3.10+、`requests` / `beautifulsoup4` / `playwright`；Node.js（可选，构建与校验） |
| 网络要求 | **演示不需要联网**（内置数据）；联网仅用于重新采集真实公开页 |

**现场演示 5 步（可断网跑）**：
1. 双击 `知时门户.html` → 左导航点「可用应用」；
2. 看雷达推送流 → 点一条卡片进详情，看「和我有关吗」逐条对照 + 溯源（点要点高亮原文）；
3. 切「问知时」问"今天有什么非要办的？"→ 看答案 + 依据一栏；
4. 切「办事日历」→ 看哪天忙、哪天能空；
5. 进「推送设置」→ 看**微信服务通知**（订阅授权 + 提前量的真实交互）与**触达时间线**（哪天会主动找你、找你几次）。

> 🎬 **录视频时照念 `docs/演示视频脚本.md`** —— 该脚本按官方四项评分维度
> （创新性 30 / 实用性 25 / 技术实现 25 / 用户体验 20）分配镜头，
> 总时长设计为 **4 分 45 秒**（给 5 分钟上限留 15 秒余量）。
