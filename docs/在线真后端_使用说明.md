## 一、三种形态怎么选

| 形态 | 文件 / 入口 | 后端 | 适用场景 |
|---|---|---|---|
| **演示版** | `知时_演示版.html` | 无；纯离线 | 答辩投屏、录视频、断网保险；刻意不接 AI 区块 |
| **参赛可用版** | `知时_可用版.html` | 构建期快照；可选本机 `127.0.0.1:8787` | 双击即开；评审现场零依赖，AI 来源如实标注 |
| **在线真后端版** | 上面的在线链接 / `知时_在线版.html` | WorkBuddy 云服务：免密钥 LLM + 云数据库 | 真正可用：实时 AI 推荐、画像上云、运行留痕 |

**三条链路互不污染**：在线版由 `tools/build_online.js` 单独构建；`build_presentation.js` 和 `build_usable.js` 都不读云配置，也不注入 SDK。因此参赛交付包里两版仍是零外链、断网可演的单文件 HTML。

## 二、在线版到底「真」在哪里

1. **免密钥大模型真调**
   - AI 推荐区块显示 `云端免密钥大模型`，`channel='workbuddy-cloud'`，`offline=false`。
   - 打开页面后，云 SDK 就绪即触发一次真实推荐；每次调用都在浏览器内逐条请求云端模型并按 `relevance / reason / evidence` 解析。
   - 模型不可用时自动回退到构建期快照或规则推荐，并如实标注降级原因，**不把规则结果冒充 AI**。

2. **云数据库持久化**
   - `zs_profile`：按浏览器端匿名 `client_id` 保存画像（身份 / 年级 / 学院 / 兴趣 / 关键词）。
   - `zs_ai_trace`：保存每次实时推荐的通道、模型、成功条数、尝试条数、耗时与时间。
   - 浏览器只持有公开配置（`endpoint` / `publishableKey` / `oauthRelayBaseUrl`），不含任何长期密钥；真正权限由服务端精确 Origin 校验约束。

3. **现场可举证**
   - 在线自检卡片直接显示通道、模型与真调条数。
   - 数据自查页 / AI 推荐区块显示实时来源，与离线快照的「构建期预计算 · 非实时调用」形成对照。

## 三、构建与部署

```powershell
node tools/build_online.js                 # 生成 知时_在线版.html（内联官方 SDK）
Copy-Item 知时_在线版.html deploy_online\index.html -Force
# 再通过发布入口把 deploy_online/ 更新到保留域名
```

构建器只读取 `知时.html`、`config/cloud.service.json`、`web/zhishi-cloud.js` 与本地 SDK 包，**不会改写演示版或参赛可用版**。

云服务应用管理入口：**设置 — 数据管理 — 应用**（可查看应用 `wbapp_fFoXXzFE9id8qgQ2Y3I1tQ` 的服务状态与数据）。

## 四、诚实边界

- 在线版依赖网络与保留域名；`file://` 本地打开或 Origin 不匹配时，会自动降级为离线能力，不会假装云端可用。
- 云数据库只存用户主动填写的画像与运行留痕，不采集成绩、课表、一卡通等私域数据。
- 在线版是**额外入口**，不改变大赛提交路径 2 的判断：离线两版仍是可复核、可现场演示的主交付。
- 如果现场网络不稳，请直接使用 `知时_演示版.html` + `知时_可用版.html`，完整演示不受影响。
