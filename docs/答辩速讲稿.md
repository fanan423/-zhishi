# 知时 · 安农校园信息雷达｜答辩速讲稿

> 用法：本稿按「**讲什么 / 怎么答 / 绝不能说什么**」组织，可打印带进答辩现场。
> 数字口径为 **2026-11-16 实测**，与包内 `data/`、`push_out/` 留痕一致。
> 作品名「知时 · 安农校园信息雷达」是提交名称；界面内已改用简明功能词（通知 / 日程 / 汇总 / 问答 / 日历），答辩时两种叫法都可，别混着说成两个产品。

---

## 0. 30 秒开场（建议背诵）

> 「大一刚入学时，我因为没看到一条通知，错过了一个本可以改变我路径的窗口。
> 后来我发现，问题不是我懒 —— 是那些通知散落在教务处、学院、学工、图书馆、公众号、班群六个地方，我**根本不知道有这回事**。
> 所以我想做一个东西：**它不等人来问，它会主动告诉你 —— 这条跟你有关，还剩几天，去哪儿办。**
> 这就是『知时』。」

（第一句请换成**你本人**的真实经历，越平实越真，这是评委最容易被打动的地方。）

**全场最重要的一句话，务必说出来：**
> **「判断发生在 AI 这边，不是发生在用户这边。」**
> 现有答疑助手解决的是「你问它答」，我们解决的是「**不问也能收到**」—— 从检索跃迁到预警。

## 1. 定位与痛点：不是懒，是信息架构问题

| 常见误解 | 真实情况 |
|---|---|
| 「学生不看教务系统是懒」 | 通知分散在六个地方，学生不知道**去哪儿找**，更不知道**有这回事** |
| 「问一下就知道了」 | 学生不知道**该问什么**。机会错过不是因为问不到，是因为不知道要问 |
| 「学校已经有答疑助手了」 | 现有助手只做「你问它答」的检索，不做「不问也给」的预警 |
| 「让 AI 帮你读通知就行」 | 只读不**核对**，用户不敢信。AI 的每个结论必须能**点回原文** |

**核心矛盾**：信息存在，但到达不了该看到它的人手上。
**我们的切口**：把 800 字通知压成 3 句人话，做成「谁能报 · 剩几天 · 怎么办」的卡片，主动送到人面前。

## 2. 产品长什么样（功能模块，用改名后的叫法）

| 模块 | 回答学生什么问题 | 亮点 |
|---|---|---|
| **通知** | 有哪些事跟我有关？ | 按可解释分数排序，只推相符通知，逐条给理由 |
| **日程** | 这周我还有几件事？ | 按截止日分五档，倒计时实时现算 |
| **汇总** | 今天一句话说清重点？ | 一句话总结 + 知时指数 + 三天内要办 |
| **问答** | 今天到底要办几件？先从哪个下手？ | 13 问 6 组，答案由真实字段算出、**附依据**、算不出就不编 |
| **日历** | 具体哪天忙、哪天能空？ | 与日程**同一批数据**，不会出现「日程 5 件、日历 3 件」 |
| **详情** | 这结论靠谱吗？ | 浓缩视图 ↔ 原文视图**双向联动高亮**，一键全部高亮 |
| **我的** | 我能控制推什么吗？ | 画像 / 关注标签 / 提前量全可控，数据只存本地 |
| **自查报告** | 你这数据可信吗？ | 三条铁律 + 疑点标注 + 可举证清单 + 审计留痕 |
| **AI 推荐**（实用版） | 按我的画像，哪条最该先看？ | 模型分 + 理由 + 逐字引文 + 规则分对照 |

**主交付形态**：原生微信小程序（`miniprogram/`，10 个页面）；
**答辩投屏/断网演示**：单文件网页（`知时_可用版.html`，双击即用、零依赖）；
**静态 10 屏演示版**：`知时_演示版.html`（刻意不接 AI，当离线保险）。

## 3. 四层链路与 AI 边界（配架构图讲）

| 层 | 做什么 | 是否用大模型 | 举证 |
|---|---|---|---|
| **采集层** | 注册表驱动，聚合公开通知页 | ❌ 确定性采集器 | `data/notices_real.json` 121 条真实通知；20 个注册源，11 源 ok / 8 源被 WAF 拦且**如实记录** |
| **理解层** ⭐ | 抽取事件类型 / 适用人群 / 截止 / 材料 / 入口五要素 + 浓缩要点 + 引文锚点 | ✅ **构建期真调** | `push_out/agent_run.json`：`mode=llm`、`model=auto`、36/36 成功、提示词 `v1.1.0` |
| **匹配层** | 画像 × 事件，AI 重排 + 规则保底 | ✅ **构建期真调** | `push_out/ai_recommend_snapshot.json`：22/22 成功、0 失败、提示词 `v1.0.0`、56 秒 |
| **提醒层** | 倒计时卡片、分类订阅、主动送达 | ❌ 端上不实时调模型 | 页面明写「构建期大模型预计算结果（非实时调用）」 |

**准确口径（背下来）**：
> 「我们用注册表驱动的采集器抓取公开通知，用**大模型在构建期做结构化理解和推荐预计算**（有运行留痕和提示词版本举证），再用**自研可解释的加权规则**做降级基线与分数对照；离线产物全部标注非实时调用，**断网可完整演示**。」

⚠️ 不要说「AI 实时智能推荐」，也不要说「整个链路纯规则」—— 两种说法都和留痕对不上。

## 4. 六个差异化亮点（回答「凭什么不是数智安农翻版」）

1. **理解后重构，不是搬运**：把 800 字压成 3 句人话，每个结论挂原文出处，点一下能核对。这叫**可信的智能**——不是「我读给你听」，是「我读完告诉你重点，且你能查证」。
2. **全链路溯源（硬活，不是装饰）**：引文在原文中做字符串定位拿到真实下标 → 把原文切成片段数组 → 点要点跳原文高亮、点原文跳回要点，**双向联动**；换个引文，高亮位置自动跟着变，是真定位出来的，不是写死的。
3. **主动划清边界**：七条渠道逐一摸过并做成可视化面板。教务处/学院/学工/图书馆官网 ✅ 已跑通；公众号 ◐ 半自动；QQ 群 ◐ 需授权；数智安农公开面 ○ 待评估；小程序 ○ 只做出口；**教务系统后台 ✕ 明确不做**（需登录态、含个人成绩学籍，技术能绕但合规不能碰）。学校 2026 年 10 月刚发《弱口令及账号权限专项排查整治》通知，此时宣称「爬教务后台」是反向踩雷。
4. **问答三条铁律**：答案必须由真实字段算出；必须附「依据」一行说明算法；算不出来就如实说算不出来。**宁可说「这条暂时算不出来」，也不给一个听起来合理但查不到的答案。**
   - 真实踩坑：最初「哪些是全校都能报的」只按受众文本匹配「全校」，把「全校第八周专业课考试安排」也当成机会列出来。修复是加**机会类标签白名单**（竞赛/奖助/讲座/图书/转专业/选课）。
5. **「各花入各眼」学院归属过滤**：通知发布在哪个学院官网，就只推给那个学院的学生；校级单位仍对全校可见。三重防误杀兜底（没填学院 / 明写「全校」 / 来源认不出 → 一律放行），**宁可多推一条给本院，也不错杀一条真机会**。
6. **日历是同一份数据的第二个视角**：日程回答「还有几件事」，日历回答「哪天忙」，结论必然自洽。

**新增第七点（本轮升级）**：实用版叠加了 **AI 推荐** —— 构建期真调模型按画像对候选通知打相关性分、生成理由与逐字引文，联网时可通过 `POST /api/recommend` 切到实时推荐；**演示版刻意零改动**（SHA256 前后一致），保持离线保险。

**合规四句话**（背下来）：
1. 数据源仅为公网公开页面，等同于「人工去各大官网翻通知」的自动化；
2. 不涉及教务系统后台，不登录、不代登录、不抓任何需鉴权系统；
3. 不采集课表、成绩、一卡通等私域与敏感数据，个性化只来自「公开信息 × 用户主动填写的关注偏好」；
4. 关注事项、提前量、提醒方式全部用户自定，数据存本地不上传。

## 7. 高频 Q&A 预演

**Q1：断网还能演示吗？**
能。模型结果在构建期就写进 `web/zhishi-ai.js` 并注入单文件应用，端上只读产物。页面如实标注「构建期预计算（非实时调用）」。规则算法始终保底，服务不可达自动降级并标注降级原因，**不会白屏也不会假装调了模型**。

**Q2：和数智安农 / 已有答疑助手有什么区别？**
它们是「你问它答」的检索，我们是「不问也给」的预警。判断发生在 AI 这边，不是用户这边。另外我们做了理解后重构 + 全链路溯源，结论能点回原文核对。

**Q3：模型到底在哪跑？现场会不会调失败？**
构建期在 Node 端跑完再注入产物，现场演示**不发起任何模型请求**，所以不存在调用失败风险。联网部署 `tools/agent/server.js` 后，`POST /api/recommend` 才实时调模型，失败自动降级。

**Q4：推荐到底是不是大模型？规则还留着干嘛？**
推荐**由模型做**（构建期 22/22 真调，按画像打相关性分并生成理由），但**规则完整保留**：一是断网/服务故障时的降级基线，二是分数对照与可解释性——页面上每条都同时展示模型理由和规则分。规则不是备胎，是可信度设计。

**Q5：数据哪来的？合规吗？**
`tools/collect_notices.py` 用 requests + BeautifulSoup 按注册表抓 20 个公开源，121 条真实通知落地，11 个源成功、8 个被 WAF 拦截并**如实记进 `source_health.json`**（不藏失败）。全是无需登录的公开页，不碰教务后台，不采个人数据。

**Q6：AI 会不会胡说？怎么核对？**
三层防线：结构化字段抽取带置信度、低置信度标「待人工核对」；浓缩要点挂引文锚点，双向联动定位到原文；问答答案必须由真实字段算出并附「依据」行，算不出就说算不出。

**Q7：为什么不做教务系统后台？技术做不到吗？**
技术能绕，但**合规不能碰**。涉及登录态与个人成绩学籍，且学校刚发账号权限排查通知。主动划红线说明作品能落地，这本身就是评审加分点。

**Q8：多少条数据？演示样例算不算造假？**
通知池 130 条，其中 121 条为 9+ 个公开通知页真实采集；少量为便于演示流程构造的示例，**已标注来源单位且一律不带官网链接**，不假装有原文。

**Q9：怎么保证日程和日历不打架？**
同一批数据、同一套倒计时现算逻辑，只是两种切法，结论必然自洽。

**Q10：为什么演示版和可用版不一样？**
刻意分层：演示版是 10 屏静态页，零依赖、当离线保险，不接 AI；实用版才是完整功能 + AI 推荐。两者共享同一份数据源，演示版 HTML 在升级前后 SHA256 完全一致。

**Q11：对应评分表吗？**
创新性 30% → 主动预警范式 + 理解后重构 + 溯源 + 划边界 + 问答引擎；实用性 25% → 真实痛点、公开源即可落地、小程序触达；技术实现 25% → 完整工作流 + 原文定位 + 倒计时现算 + 受众防误杀 + 20+ 校验脚本双层防线；用户体验 20% → 三问式卡片、双向联动、订阅全可控。

**Q12：现在能直接提交吗？**
作品本身齐了，但按官方路径 2 还差三件人工事项：**5 分钟演示视频 MP4**（路径 2 的主要评审依据）、**封面实名信息（姓名/学号/电话）**、**上传云盘（密码 1234）+ 群内回复「已提交」**。截止 2026-12-03 23:00。
