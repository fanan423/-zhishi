知时 · 主动通知 Demo 使用说明
============================================================

一、这个 Demo 是什么
------------------------------------------------------------
把「用户不开小程序也能收到通知」这条链路完整跑给你看，且每一步都是
真实调用服务端接口，不是静态示意图：

  ① 授权   wx.requestSubscribeMessage（必须由用户点击，一次授权换一条）
  ② 登记   openid + 订阅类别 + 提前量 → 服务端登记表（授权额度池）
  ③ 触发   定时（默认每天 08:00）或页面上的「立即跑一轮」
  ④ 决策   复用 /api/digest 清单 + 提前量节点 + 类别 + 额度 + 去重
  ⑤ 下发   sender 适配器：file（默认，落盘模拟）/ wechat（真调微信）
  ⑥ 回执   写 inbox、扣额度、记日志；点开服务通知产生已读回执

默认处于「演示模式」：链路真实执行、消息真实落盘，页面用微信服务通知
卡片呈现，但不会冒充已经发到微信。这一点在页面顶部和状态里如实标注。


二、三步启动（不用微信开发者工具、不用小程序后台、不用公网）
------------------------------------------------------------
1. 完整解压压缩包（保持目录结构，别只拖单个文件）。
2. 双击「双击启动通知Demo.bat」。黑窗口别关。
3. 浏览器自动打开 http://127.0.0.1:8790/ ；没弹出就手动敲这个地址。

需要 Node.js 18+（https://nodejs.org）。没装的话 bat 会提示并停下。
端口 8790 是刻意和小程序智能体服务（8787）分开的，两个可以同时开。

页面上按顺序点：
  开启提醒（授权） → 立即跑一轮 → 看左侧「微信服务通知」卡片 →
  点开任意一条（产生已读回执） → 看右侧决策明细 / 下发明细 / 运行日志。

「强制重跑」可忽略去重重复演示；「重置演示」清空登记与消息重新来。


三、为什么默认是演示模式，怎么切成真下发
------------------------------------------------------------
微信订阅消息有三个绕不开的前提：小程序后台申请模板、AppID/AppSecret、
服务端能访问微信接口且真机能连到。缺任一项都发不出去，所以代码不会
假装能发。

在 agent-server/push_out/ 下新建 notify_config.json：

{
  "appid": "wx你的AppID",
  "appsecret": "你的AppSecret（只放服务端，绝不放前端）",
  "templates": {
    "deadline":  "模板ID_截止提醒",
    "newnotice": "模板ID_新通知提醒",
    "weekly":    "模板ID_每周简报"
  },
  "sendAt": "08:00",
  "jumpPage": "pages/detail/detail",
  "mpState": "trial",
  "fieldMap": {
    "deadline":  { "thing1": "事项名称", "time2": "截止时间", "number3": "剩余天数" },
    "newnotice": { "thing1": "通知标题", "time2": "发布时间", "thing3": "来源" },
    "weekly":    { "number1": "本周事项数", "thing2": "最紧急一项", "time3": "截止日" }
  }
}

也可以用环境变量：WX_APPID / WX_APPSECRET / WX_TMPL_DEADLINE /
WX_TMPL_NEWNOTICE / WX_TMPL_WEEKLY / WX_SEND_AT / WX_MP_STATE。

配齐 appid + appsecret + 至少一个模板 ID，重启服务，状态会自动从
「演示模式（落盘模拟）」变成「真实下发（微信订阅消息）」，其余代码不用改。

fieldMap 的键（thing1/time2/number3…）必须和你后台申请的模板关键词
逐个对齐；对不上就改这里，代码会如实返回失败原因，不会静默吞掉。


四、三个硬约束（答辩常被问到）
------------------------------------------------------------
1. 一次性订阅：一次授权换一条推送。长期订阅只对政务、医疗等类目开放，
   校园通知类一般拿不到。所以做了授权额度池 + 「补一次授权」，靠用户
   每次进小程序补授权来攒 7/3/1 三次提醒的额度。
2. 模板字段：data 的字段名必须与后台模板关键词严格一致，且 thing 类型
   有 20 字符限制（代码已截断）。
3. 真机/上线：正式下发要 https 公网或云函数定时触发，不能填 127.0.0.1；
   本机演示靠开发者工具「不校验合法域名」+ 落盘模拟。


五、新增接口（GET /api 可看完整清单）
------------------------------------------------------------
GET  /api/notify/status      模式、模板、额度、定时、上线 checklist
POST /api/notify/subscribe   授权登记（写 openid / 类别 / 提前量 / 额度）
POST /api/notify/topup       补一次授权
POST /api/notify/run         跑一轮：决策 → 下发 → 回执（支持 force）
GET  /api/notify/inbox       微信服务通知收件箱（可按 openid 筛）
POST /api/notify/read        点开消息 → 已读回执
GET  /api/notify/log         运行日志
POST /api/notify/reset       清空演示数据（配置不变）

落盘产物在 agent-server/push_out/：
  notify_store.json          登记表 / 消息 / 日志 / 去重键
  notify_out/*.json          每条下发消息
  notify_out/下发总表.json   下发流水
  notify_config.json         真下发配置（自己新建，默认不存在）


六、小程序本体怎么接
------------------------------------------------------------
utils/wxnotify.js 已补服务端联动：授权后自动把 openid、类别、提前量
POST 到 /api/notify/subscribe；另提供 serverStatus() / serverInbox() /
markServerRead() / topUpServer() 供页面调用。地址复用 app.js 的
agentBase（可在「我的 → 智能体服务 → 改地址」运行时修改），服务端不可达
时静默降级，不影响小程序原有功能。

跑小程序时双击「双击启动智能体.bat」（8787），再在开发者工具里编译；
跑通知 Demo 时双击「双击启动通知Demo.bat」（8790），浏览器看链路。


七、常见问题
------------------------------------------------------------
· 浏览器打不开 → 看黑窗口是不是报端口占用；8790 被占就改 bat 里的端口。
· 跑一轮显示「跳过」→ 看决策明细：一般是没到提前量节点、额度用完、
  或本节点已发过（勾「强制重跑」或点「重置演示」）。
· 授权额度为 0 → 点「补一次授权」，这正是微信一次性订阅的真实约束。
· 想看清单本身 → GET /api/digest 或页面「决策明细」里的分数与推送理由。
· 黑窗口关掉 = 服务停止；定时触发也停。长期用就保持窗口开着或配成服务。
